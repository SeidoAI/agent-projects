# tripwire v0.13.1 — WS4-residual cutover, recovery ergonomics, Gap B side-effect

## Context

v0.13.0 converged the session lifecycle on a single executor — schema,
registry, dispatcher, and the central `tripwire session transition`
caller — but four classes of work were deliberately deferred:

1. **WS4-residual.** The dedicated session commands (`complete`,
   `abandon`, `reopen`) and the programmatic callers
   (`pr_watcher_executor`, `monitor_actions`,
   `ui/services/action_service`) still mutate `session.status`
   directly, bypassing `execute_transition`. Six call sites total. Until
   they cut over, the v0.13 "single writer of `session.status`" guarantee
   holds only on the explicit-transition path; the dedicated commands
   keep their pre-v0.13 behavior.

2. **PM handoff #5 Gap B.** The squash-merge orphan-branch problem on
   reopen. The route `paused-to-executing` exists with `preserve_fields`
   declared, but the new `normalise_after_squash_merge` side-effect
   handler that resets the worktree onto `origin/<base>` when its branch
   was squash-merged isn't implemented yet. Gap B is the only PM-handoff
   #5 remedy that isn't already a data-only YAML edit; it needs real
   git plumbing.

3. **PM handoff #6 recovery ergonomics — R3, R4, R6.** Three remedies
   from the 2026-05-08 stuck-loop incident (full text in
   `docs/handoffs/2026-05-08-pm-handoff-6.md` if planted; otherwise see
   the conversation transcript). R3 wants `cleanup` to optionally
   preserve agent-authored uncommitted work; R4 wants `spawn` to handle
   a pre-existing remote branch with commits ahead of base; R6 wants
   `--resume` to be valid from any state where
   `runtime_state.claude_session_id` is populated.

4. **Migration tooling polish.** `tripwire migrate workflow` shipped in
   v0.13.0 but only handles the byte-identical-to-v0.12-template happy
   path and a single force-overwrite escape hatch. Production projects
   that hand-edited their workflow.yaml need a 3-way merge or at least
   a richer diff-and-confirm flow.

Out of scope:

- **PM handoff #6 R1** (bash bg-task 0-byte output capture). This is a
  Claude Code framework problem, not a tripwire problem. Tripwire is
  structurally incapable of fixing it. Track separately at the framework
  level.
- **PM handoff #6 R5** (validate-on-edit hook scope). The hook itself
  lives in `.claude/hooks/` (or a packaged equivalent) and runs full
  `validate_project`. Scoping it to "diff against pre-edit state" or
  "session/issue subtree only" is a hook redesign that lives outside
  the workflow refactor.
- **Multi-workflow runtime.** The eleven non-coding-session workflows
  remain in `docs/workflows/legacy-workflows.md` as documentation. Any
  one of them becoming runtime-active is a v0.14 concern.

## Architectural target

The v0.13 executor diagram from `2026-05-XX-v013-workflow-executor.md`
already captures the runtime shape. v0.13.1 adds:

- **No new architectural surface.** The seven cutover sites all become
  thin wrappers around `execute_transition` (with the route id resolved
  from current+target status, plus per-caller `flags`). The
  `normalise_after_squash_merge` handler is a new entry in the existing
  side-effect registry. R3/R4/R6 ergonomics are CLI-flag additions on
  the existing spawn/cleanup commands. Migration polish is wholly inside
  `cli/migrate.py`.

The result is that after v0.13.1, the executor truly is the sole writer
of `session.status` (no remaining direct-mutation sites), the recovery
flow from PM handoff #6 collapses from 14 manual steps to 2, and Gap B
becomes a one-flag spawn rather than a destroy-and-redo.

### WS1 — Executor extension: caller-resolved route ids + nullable target_status

**File:** `src/tripwire/core/workflow/transitions.py`

Today `execute_transition(project_dir, session_id=, target_status=)`
infers the route from `(current_status, target_status)`. The dedicated
commands need a slightly richer surface:

- Accept `route_id: str | None = None` directly. When non-None, the
  executor looks the route up by id (fail-loud on unknown id) instead
  of resolving from the status pair. Lets `complete_session_cmd` say
  `route_id="verified-to-completed"` unambiguously even when the
  current session is already at `verified` (no ambiguity, but explicit).
- Allow `target_status` to remain optional when `route_id` is supplied;
  derive it from `route.to_ref`.
- When neither is given, raise `TransitionError`.

### WS2 — Callers cutover (close out WS4-residual)

**Files (in dependency order):**

| Caller | Route id |
|---|---|
| `core/session_complete.py:complete_session` | `verified-to-completed` |
| `core/session_abandon.py:abandon_session` | `*-to-abandoned` (resolved from current_status at call time) |
| `core/session_reopen.py:reopen_session` | `completed-to-paused-reopen` |
| `core/pr_watcher_executor.py:206` | resolve from current+target |
| `runtimes/monitor_actions.py:159` | resolve from current+target |
| `ui/services/action_service.py:325, 348` | resolve from current+target |

For each: replace direct `session.status = SessionStatus.X; save_session(...)`
with `execute_transition(project_dir, session_id=sid, route_id=R,
flags={...})`. The dedicated modules become thin wrappers — their
existing pre-flight checks (e.g. `_verify_pr_merged` in
session_complete) are already registered as side-effects on the
matching route, so they fire from the executor's run loop, not the
function body.

After this WS, the only direct `session.status = ...` writes in the
codebase should be inside `execute_transition` and its rollback path.
Add a CI check (`grep -rn 'session.status = ' src/ | grep -v transitions.py`
should be empty).

### WS3 — `normalise_after_squash_merge` side-effect handler (Gap B)

**File:** `src/tripwire/core/workflow/side_effects.py`

Register a new handler:

```python
def _normalise_after_squash_merge_apply(ctx: SideEffectContext) -> SideEffectResult:
    """Reset each session worktree's branch to origin/<base> when the
    branch's PR was squash-merged. Idempotent: a branch already
    matching origin/<base> is a no-op."""
```

Detection: for each worktree entry,
- `git fetch origin` inside the worktree.
- Read the PR state via `gh pr view <branch> --json state,mergeStateStatus,mergeMethod`. If state is `MERGED` and mergeMethod is `SQUASH`, proceed.
- Confirm divergence: `git log origin/<base_branch>..HEAD --oneline` non-empty (the branch has commits that aren't on main).
- On match: `git reset --hard origin/<base_branch>` inside the worktree.

Wire into the `paused-to-executing` and `failed-to-executing` routes in
`templates/workflow.yaml.j2` as a side-effect, conditional on a flag
(`from_squash_merge: true`). The flag is set by `tripwire session reopen`
when the session's PR(s) have already merged on origin (use
`gh pr view ... --json state` once during reopen).

Idempotent and best-effort: declare `idempotent=True` so the executor
doesn't try to invert it. Inverse is unsafe — we'd have to recreate
commits we threw away.

### WS4 — Recovery ergonomics: R3 + R4 + R6 from PM handoff #6

#### R3 — `cleanup --preserve-work`

**File:** `src/tripwire/cli/session.py:cleanup_session_worktrees` (1266–1391)

New flag `--preserve-work`. When set, before removing each dirty
worktree:

1. Compute the diff: `git status --porcelain` inside the worktree.
2. Partition modified files by path-prefix into:
   - **Agent-authored** (anything outside `.claude/`, `.tripwire/`,
     `CLAUDE.md`, `CLAUDE.md.bak`, `.git/info/exclude` mutations).
   - **Scaffold noise** (everything else).
3. Stage only agent-authored paths. Commit with message
   `WIP({sid}): preserved before cleanup`. Push to `origin/<branch>`.
4. Discard scaffold-noise (it'll be re-rendered on next spawn). Then
   proceed with the existing remove logic.

If the agent-authored set is empty, behave as today (skip dirty unless
`--force`). New flag `--cleanup-dry-run` (renamed from --dry-run if it
collides) prints the partitioned tree without acting.

#### R4 — Spawn handles pre-existing remote branch

**File:** `src/tripwire/runtimes/prep.py:resolve_worktrees_for_session`

Today `worktree_add` creates `<branch>` from `<base_branch>` and
`_open_draft_pr` opens an empty marker commit + push. When
`origin/<branch>` already exists with commits beyond base, the push is
non-FF and the spawn aborts mid-prep.

Fix: before creating the branch, check for `origin/<branch>` via
`git ls-remote origin refs/heads/<branch>`. If present:

- Use `worktree_attach` (already exists for v0.12.1's `--resume`
  recreate) to attach the existing remote branch as the worktree, NOT
  a fresh-from-base branch.
- Skip the empty `session({sid}): start` marker commit (it's a no-op
  when there's substantive history).
- Skip the initial push (the remote already has these commits).
- Still attempt `gh pr create --draft` for the worktree branch only if
  no PR exists yet (`gh pr list --state all --head <branch> --json number`
  empty).

This makes "preserve partial work + fresh agent conversation" a
first-class flow. PM handoff #6 step 12 (destroying remote branch state
to unblock spawn) becomes unnecessary.

#### R6 — `--resume` valid from any state with `claude_session_id`

**File:** `src/tripwire/cli/session.py:session_spawn_cmd` (~line 569)

Today the `--resume` precheck rejects unless `session.status` is
`paused` or `failed`. Replace with: `--resume` is valid iff
`session.runtime_state` is populated AND
`session.runtime_state.claude_session_id` is non-empty AND
`session.runtime_state.worktrees` is non-empty.

The status check moves to a **post-resume normalise**: after a
successful runtime restart, the executor flips session status to
`executing` via `execute_transition` with the appropriate
`*-to-executing` route. The route handles preserve_fields and any
side-effects. If no such route exists from the current status, that's
a transition_not_reachable error surfaced to the operator.

### WS4-bis — Migration polish

**File:** `src/tripwire/cli/migrate.py:migrate_workflow_cmd`

The current `--yes` is a hard overwrite. Add:

- `--diff` flag: print a side-by-side or unified diff between the
  existing file and the v0.13 template. Exits 0; pure inspection.
- `--merge` flag (stretch): for each `coding-session` route in the
  existing file, if the route id is in the v0.13 template, pick the
  v0.13 shape but preserve any `controls.tripwires`,
  `controls.heuristics`, `controls.jit_prompts`,
  `controls.prompt_checks`, and `skills` arrays from the user's file
  (these are the customization surface). Emit per-route conflict
  warnings for routes the user added that aren't in v0.13. Write
  output; on any unresolvable conflict, refuse and print the conflict
  list.
- `--check` flag: returns exit 1 if the file needs migration, exit 0
  if already on schema_version 1. Useful for CI gates.

## Risk register

| Risk | Early signal | Mitigation |
|---|---|---|
| Cutting over `complete_session` changes the gate ordering (today: flip drafts → verify PRs → verify review → verify artifacts → sweep → status flip; v0.13: side_effects array order). | Ship a behavior-equivalence test that drives complete_session pre- and post-cutover and asserts identical event sequences. | Pin the side_effects order in `verified-to-completed` to match the existing function's order: `[verify_prs_merged, verify_review_ok, verify_issue_artifacts, flip_drafts_to_ready, sweep_issues_forward, remove_worktrees, append_telemetry_row]`. |
| `--resume` from arbitrary status causes session.status to land somewhere unexpected when no route exists from `<current> → executing`. | Explicit `transition_not_reachable` error from the executor; operator can pivot. | Document the new `--resume` semantics in `docs/handoffs/...`: "valid from any state with claude_session_id; failure means the workflow.yaml has no route from the current state to executing." Project workflow.yaml customisations should ensure such routes exist. |
| `cleanup --preserve-work`'s partition heuristic mis-classifies an agent-authored file under `.claude/` (e.g. an agent that intentionally edited a skill). | Run `--cleanup-dry-run` shows the partition; reviewer can spot. | Document the partition rule in the cleanup help text. Provide a `--preserve-work-include <path>` override flag for edge cases. |
| `gh pr view` rate limits during many concurrent reopens (Gap B side-effect probes). | gh CLI returns 403/rate-limit. | Cache the squash-merge probe per session for the lifetime of the executor call. Side-effect handler treats gh failure as "best-effort skip" (idempotent=True). |
| The R4 spawn-from-existing-remote-branch flow collides with the v0.12.1 `--resume` worktree-recreate logic (which does its own ad-hoc thing). | Integration test that exercises both paths against the same branch. | Unify: both paths call into one `recreate_or_attach_worktree` helper, parameterised by `mode={resume_from_completion, fresh_conversation, fresh_branch}`. |
| Migrate `--merge` flag accidentally drops user-customised side-effects. | Per-route conflict warning. | Warn loudly on routes whose `side_effects:` array exists in the user's file but doesn't match v0.13. Refuse without `--yes` if any conflict can't be auto-resolved. |
